# ++PHP 2026.3.1-rc-2

++PHP `2026.3.1-rc-2` is a release candidate for a PHP source language that adds compile-time safety and expressive type features, then produces ordinary PHP 8.4 for deployment.

This is a prerelease. It is suitable for evaluation and early project use, but language behavior and generated output may still change before the first Stable release. The candidate is prepared but has not yet been published to GitHub Releases or Packagist.

## Installation

After publication, install the exact release-candidate version:

```bash
composer require --dev atatusoft-ltd/ppphp-src:2026.3.1-rc-2
```

Until then, evaluate the candidate from a repository checkout with its locked dependencies.

## Requirements

- PHP `^8.4` for the compiler
- Composer 2
- At least 512 MiB of memory available to compiler processes

Generated applications target PHP 8.4.

## What Improved

- Typed locals accept valid concatenations and broader declared types without false PHPDoc errors. Closure and arrow-function locals work with both `Closure` and `callable`, preserving their signatures for PHP tools.
- `when` expressions accept valid branch values in returns, arguments, arrays, and nested expressions without false PHPDoc errors or artificial nullable results.
- Generated PHP no longer contains blank indentation-only lines where a `throws` clause was removed; source locations remain accurate.
- Missing-type messages use plain language. Initialization errors identify the affected template or release file, and commands explain when too many paths were supplied.
- Errors give more specific explanations: a missing `<?php` tag is reported directly, configuration failures keep their actionable details in editors, and analysis failures no longer automatically suggest changing cache permissions.

- Editor integrations can check unsaved code, including changes in other open files, without saving or rebuilding your project. Full saved-file checks remain available for additional analysis.
- Type errors now preserve the spelling and capitalization of fully qualified class and interface names, making diagnostics easier to compare with source code.
- Nullable values narrowed by a preceding guard can now initialize non-null local variables without a false type error.
- An assigned but unread private property now produces a warning instead of blocking a build.
- Existing strict checks, source mapping, deterministic output, incremental caching, and mixed PHP/++PHP builds remain available from the first candidate.

## Quick Start

From a project where ++PHP is installed:

```bash
vendor/bin/ppphp init
vendor/bin/ppphp composer:configure --dry-run
vendor/bin/ppphp composer:configure
composer update --lock --no-interaction --no-scripts
composer dump-autoload --optimize
vendor/bin/ppphp check
vendor/bin/ppphp build
```

Run the application from the generated `build/ppphp` tree. Do not execute `.ppphp` source files directly.

## Major Features

- Strict project-wide checks for local variables, arguments, returns, properties, calls, nullable values, collections, generics, and checked errors.
- Explicitly typed mutable and readonly local bindings, including typed `for` and `foreach` declarations.
- Union, intersection, and DNF types; erased generics; and typed list and map arrays.
- Checked `throws` contracts and value-producing `when` expressions.
- Mixed `.php` and `.ppphp` projects, allowing gradual adoption without rewriting ordinary PHP source.
- Composer-aware declaration analysis for installed packages without executing dependency code.
- Deterministic, atomic builds with source maps, manifests, PHP lint validation, and recovery after interruption.
- Hash-verified caching for unchanged analysis and generated artifacts.
- Stable console and JSON diagnostics mapped back to original source locations.

## Compatibility And Deployment

++PHP source uses the `.ppphp` extension and the normal PHP opening tag. Ordinary `.php` files keep PHP behavior and are copied byte-for-byte into selected build output. `.ppphp` files receive the stricter language contract and compile to `.php`.

The Composer package is `atatusoft-ltd/ppphp-src`, the command is `ppphp`, and the canonical compiler namespace is `Atatusoft\Ppphp`. Compiler classes are not a public plugin API for this release.

A complete `ppphp build` validates the project before atomically replacing the configured output, which defaults to `build/ppphp`. Generated files require no ++PHP runtime library unless the source itself imports an ordinary package. Keep hand-written files outside the configured output and deploy the generated tree with the root Composer metadata and installed dependencies.

## Known Limitations

- Generated source targets PHP 8.4.
- Native `ppphp check` and `ppphp build` include supplemental PHPStan analysis.
- Deep analysis of ordinary PHP implementation bodies is supplied by PHPStan.
- Generator-specific compiler-owned flow analysis remains limited.
- Browser compiler analysis is an internal integration protocol rather than a supported browser build product.
- No formatter is included.
- No standalone language server is included in this repository.
- Immutable Records, postfix list syntax, Native Type Members, and attribute factory expressions are future work and are not part of this release.

## Upgrade Notes

Projects using the first candidate can update the version constraint and rebuild cleanly:

```bash
composer require --dev atatusoft-ltd/ppphp-src:2026.3.1-rc-2
vendor/bin/ppphp clean
vendor/bin/ppphp build
```

Report vulnerabilities privately according to the [security policy](https://github.com/atatusoft-ltd/ppphp-src/blob/2026.3.1-rc-2/SECURITY.md). Do not include credentials or other secrets in reports.
